# Synthetic NIAH inputs

All files here are synthetic multi-key needle-in-a-haystack (NIAH) datasets
generated by [`../scripts/build_niah.py`](../scripts/build_niah.py), not
downloaded from anywhere. Each example embeds `n_keys` (key, value) pairs in
filler distractor text at a target context length, and asks for the value of
one specific key; correctness is exact match on the integer answer.

Regenerate any file with:

```bash
python ../scripts/build_niah.py --n_keys <K> --target_tokens <N> --out <path>
```

## Files

| file | n_keys (from filename) | target context |
|---|---:|---:|
| `niah_multikey.jsonl` | 4 (default) | ~16K tokens |
| `niah_multikey_4k.jsonl` | 4 | ~4K tokens |
| `niah_4k_K1.jsonl` .. `niah_4k_K32.jsonl` | 1, 2, 4, 8, 16, 32 | ~4K tokens |
| `niah_8k_hard.jsonl`, `niah_8k_hard16.jsonl`, `niah_8k_hard32.jsonl` | varies (see filename) | ~8K tokens |

`niah_multikey.jsonl` is `h1_sweep.py`'s default input (`--data`). The K- and
hard-variant files are exploratory generations from a `--n_keys` sweep not
wired into any script currently in `experiments/scripts/`; they are kept for
reproducibility of whatever produced them, and are safe to delete/regenerate
if not needed.

Fields: `{id, context, question, answer, keys, values, target_idx,
n_filler_tokens}`. `context` and `question` are the model input; `answer` is
the exact-match target.

These are all zero-cost to regenerate (a few seconds, no GPU, no external
download) — they are committed only so results are reproducible from a fixed
draw without re-running the generator.
